DeepSeek LLM

Paper| Code

数据预处理：包括去重、筛选、重新混合。去重在整个CommonCrawl数据集上操作，而不是在每个dump里去重。筛选标准包括词法和语法评估。数据混合增加罕见领域的数据出现以改进数据不均衡问题。

tokenization：同GPT-2，先预分词以避免换行、标点符号和CJK字符的合并。数字拆成单独的数位。tokenizer为Byte-level Byte-Pair Encoding。利用约24G多语言语料获得100000个tokens，考虑到训练效率和特殊token，训练词表大小设为102400。

模型架构：遵循LLaMA，使用RMSNorm的Pre-Norm结构，激活函数用SwiGLU，中间层维度\(8/3*d_{model}\) ，位置编码用旋转编码。67B模型使用GQA替代MHA，GQA在深度上扩展参数而不是宽度上。为利用流水线并行，7B模型有30层，67B模型有95层。

超参数：权重初始化标准差0.006，优化器AdamW，\(\beta_1\)=0.9，\(\beta_2\)=0.95，weight_decay = 0.1。使用multi-step learning rate scheduler，热身2000步达到最大学习率，处理80%的tokens后减少到31.6%，90% tokens后减少到10%。梯度裁剪阈值为1.0。

训练设施：用HAI-LLM框架训练，支持数据并行、张量并行、序列并行和1F1B流水线并行。使用flash attention，利用ZeRO-1在数据并行]设备之间划分优化器状态。优化计算和通信时间减少等待开销。融合部分层和算子加速训练。用bf16精度训练，fp32精度累积梯度。交叉熵CUDA核函数里，内部动态地将bf16精度转换为fp32，计算梯度后，直接用梯度覆盖 logits，避免额外的显存占用。每5分钟异步保存模型，并定时清理。支持从不同3D并行里恢复训练。使用vLLM评估生成任务，使用连续批处理评估非生成任务。

scaling laws：

  • batch size和学习率可以在相对较宽的参数空间内可以实现接近最佳的性能。

  • \(\eta_{opt}=0.3118\cdot C^{-0.1250}\)

  • \(B_{opt}=0.2920\cdot C^{0.3271}\)

  • \(C=MD\), C for compute budget, D for data scale, M for non-embedding FLOPs/token

  • \(𝑀_{opt} = 𝑀_{base} ·𝐶^𝑎, 𝑀_{base}=0.1715, 𝑎=0.5243\)

  • \(𝐷_{opt} = 𝐷_{base} ·𝐶^𝑏, 𝐷_{base}=5.8316,𝑏 = 0.4757\)

  • 随着数据质量的提高，模型缩放指数a逐渐增加，数据缩放指数𝑏减小，即增加计算预算应该更多地分配给模型而不是数据。

预训练：在2T中英数据上预训练，数学推理等任务能跨语言迁移，中文数据有助于中文任务。

对齐：包括SFT和DPO。总计1.5M中英指令数据，其中1.2M任务数据，300K安全数据。SFT里，7B模型训练4epochs，76B模型训练2epochs。DPO里训练1epoch。7B模型里先用全量数据训练，再用去掉代码和数学数据的数据训练以降低重复输出。从预训练和微调里去掉多选数据以避免过拟合。

DeepSeek MOE

Paper | Code

细粒度专家细分：在典型MoE架构的基础上，把FFN中间隐藏维度减少到原始的1/m，把激活的专家数量增加到m倍。

隔离共享专家：隔离一些专家作为共享专家以获取通用知识。

\[ \mathbf{u}^l_{1:T}=Self–Att(\mathbf{h}^{l-1}_{1:T})+\mathbf{h}^{l-1}_{1:T} \]

\[ \mathbf{h}_t^l=\sum^{K_s}_{i=1}FFN_i(\mathbf{u}^l_t)+\sum^{mN}_{i=1}(g_{i,t}FFN_i(\mathbf{u}^l_t))+\mathbf{u}^l_t \]

\[ g_{i,t}=\left\{\begin{array}{rcl}s_{i,t} & {s_{i,t}\in Topk(\{s_{j,t}|K_s+1\leq j \leq mN\},mK)}\\0 & otherwise\end{array}\right. \]

\[ s_{i,t}=Softmax_i(\mathbf{u}_t^{lT}\mathbf{e}_i^l) \]

专家和设备的负载均衡：避免总是选择少数专家，缓解设备不平衡的计算瓶颈。

\[ \mathcal{L}_{ExpBal}=\alpha_1\sum^{N^\prime}_{i=1}f_iP_i,\ f_i=\frac{N^\prime}{K^\prime T}\sum^T_{t=1}\mathbb{I}(Token\ t\ selects\ Expert\ i),\ P_i=\frac{1}{T}\sum^T_{t=1}S_{i,t} \]

\[ \mathcal{L}_{DevBal}=\alpha_2\sum^{D}_{i=1}f_i^\prime P_i^\prime ,\ f_i^\prime =\frac{1}{|\varepsilon_i|}\sum_{j\in\varepsilon_i}f_j,\ P_i^\prime=\sum_{j\in\varepsilon_i}P_j \]

验证模型：9层Transformer，隐藏维度1280，10个注意力头，初始化标准差0.006，总专家参数为标准FFN的16倍，激活专家参数为标准FFN的2倍，总模型参数约2B，激活参数约0.3B。

训练：优化器AdamW，\(\beta_1\)=0.9，\(\beta_2\)=0.95，weight_decay = 0.1，前2000步热身，到80%时衰减0.316，到90%再衰减0.316，最大学习率1.08e-3。梯度裁剪阈值为1.0。batch size = 2K，最大序列长度2K，对100B tokens训练25000步。

DeepSeekMoE 2B的性能与GShard 2.9B相当，在总参数量相同的情况下接近稠密模型的性能。16B模型与LLaMA2 7B性能相当，仅需约40%的计算。

DeepSeek Coder

Paper | Code

数据：87%源代码，10%代码相关英文自然语言，3%代码相关中文自然语言，总计798G，603M文件。收集了87种语言的GitHub公开仓库，过滤后留下32.8%，过滤过程：过滤掉平均行长度超过100个字符或最大行长度超过1000个字符的文件，过滤掉字母少于25%的文件，除XSLT语言外过滤掉前100行包含xml头字符串的文件，过滤掉可见文本不超过20%或不超过100个字符的html文件，过滤掉字符数少于50或大于5000的json或yaml文件。对一个项目代码，先解析文件依赖，然后通过文件依赖图按节点度排序，即可确保每个文件所依赖的上下文在输入序列中位于该文件之前。训练数据相似去重可改善性能，因此进行仓库层面的近似去重。利用编译器和质量模型和启发式规则，进一步去除包含语法错误、可读性差、低模块化的低质量数据，并利用n-gram去除包含在验证数据里的代码。

tokenizer、模型架构、优化器、训练环境基本同DeepSeek LLM。

训练目标：next token prediction和fill in the middle。FIM是为了学会在中间插入代码，具体操作是把文本随机切分成三份，打乱顺序后按不同部分用特殊字符连接，顺序包括Prefix-Suffix-Middle和Suffix-Prefix-Middle两种。

长上下文：配置RoPE参数扩展默认上下文窗口，采用线性缩放策略，将缩放因子从1增加到4，并将base frequency从10000增加到100000，使用batch size 512和序列长度16K额外训练1000步，学习率同最后一阶段。理论上可以处理64K长度，实际上最大可靠长度为16K。

微调：使用100步热身的cosine schedule，初始学习率1e-5，batch size 4M，总共训练2B tokens。

继续预训练：从DeepSeek-LLM-7B Base使用代码数据继续预训练，仅使用NTP任务，窗口长度4K，相比Coder模型，编码任务表现有所减弱，但数学推理和其他自然语言任务显著提升。

DeepSeek Math

Paper | Code

DeepSeekMath Corpus：首先使用OpenWebMath作为种子语料训练数学相关分类模型，从OpenWebMath和CC里各随机采样500K条数据训练fasttext分类器，对CC数据通过URL和相似去重后，利用分类器判断数学相关语料，按预测分排序后保留一定规模数据，计算结果里同一个URL占总数据的比例，对超过10%的URL标记为相关语料，按URL添加到标注语料里，重复上面过程，四轮后新增数据降到2%停止迭代，最终获得35.5M数学网页，120B tokens。同样利用n-gram去除包含在验证数据里的代码。

基础模型为DeepSeek-Coder-Base-v1.5 7B，预训练500B tokens，包括：56% DeepSeekMath Corpus, 4% AlgebraicStack, 10% arXiv, 20% Github code, 10% 中英CC，预训练基础同DeepSeek LLM。

代码训练有助于数学推理。Arxiv论文训练对数学推理无用。

SFT：数据为中英文各领域数学问题，加不同解决方式：chain-of-thought, program-of-though, tool-integrated reasoning format。共776K条数据。训练数据随机拼接到最大上下文长度4K tokens，batch size 256，学习率5e-5，训练500步。

强化学习：强化学习可以在SFT后有限提升数学推理能力。PPO里通过在每个token时从参考模型即SFT模型添加逐token的KL惩罚，和策略模型一起训练价值函数，减轻奖励模型的过度优化。GRPO不需要价值函数，使用同一问题的多个输出采样的平均奖励，也不在奖励函数里使用KL惩罚，直接把KL散度添加到损失函数里。对完整输出结果优化策略(过程监督)，对每一步推理优化监督(过程监督)。根据策略模型的采样结果为奖励模型生成新的训练集，并使用包含10%历史数据的重放机制不断训练旧的奖励模型。然后将参考模型设置为策略模型，并用新的奖励模型不断训练策略模型。强化学习通过使输出分布更加稳健来提高模型的整体性能，这种改进是由于提高了TopK的正确回答，而不是增强了基本能力。

训练方法范式：各种训练方法的参数优化包含三个关键部分：数据源，奖励函数，学习算法。

  • Supervised Fine-tuning (SFT)：在人工选择的SFT数据上微调预训练模型，无奖励函数。

  • Rejection Sampling Fine-tuning (RFT)：对SFT模型的对SFT问题的回答经过质量过滤和多样性控制后的过滤数据进一步微调SFT模型，奖励函数为规则。

  • Direct Preference Optimization (DPO)：对SFT模型的增强输出使用DPO损失函数进一步改进SFT模型，奖励函数为规则。

  • Online Rejection Sampling Fine-tuning (Online RFT)：使用SFT模型初始化策略模型，并通过使用从实时策略模型中采样的增强输出进行微调，奖励函数为规则。

  • PPO/GRPO：使用SFT模型初始化策略模型，并用从实时策略模型中采样的输出对其进行强化，奖励函数为模型。

DeepSeek V2

Paper | Code

模型架构：对Transformer架构，把attention优化为Multi-head Latent Attention (MLA)，FFN优化为DeepSeekMoE架构。MLA的核心是对键和值进行低秩联合压缩以减少KV缓存，修改ROPE为解耦方式，推理时仅缓存\(\mathbf{c}_t^{KV}\)和\(\mathbf{k}^R_t\)。训练时也对query同样操作以减少激活内存。

\[ \mathbf{c}^Q_t=W^{DQ}\mathbf{h}_t \]

\[ \mathbf{q}^C_t=W^{UQ}\mathbf{c}^Q_t \]

\[ \mathbf{q}^R_t=ROPE(W^{QR}\mathbf{c}^Q_t) \]

\[ \mathbf{q}_{t,i}=[\mathbf{q}^C_{t,i};\mathbf{q}^R_{t,i}] \]

\[ \mathbf{c}^{KV}_t=W^{DKV}\mathbf{h}_t \]

\[ \mathbf{k}^C_t=W^{UK}\mathbf{c}^{KV}_t \]

\[ \mathbf{k}^R_t=ROPE(W^{KR}\mathbf{h}_t) \]

\[ \mathbf{k}_{t,i}=[\mathbf{k}^C_{t,i};\mathbf{k}^R_{t,i}] \]

\[ \mathbf{v}^C_t=W^{UV}\mathbf{c}^{KV}_t \]

MoE里除了简单的前K名路由专家外，还确保每个token的目标专家分布在最多M个设备上，对每个token，首先选择包含最高得分的专家的M个设备，然后在这些设备的专家中进行前K选择。除专家和设备均衡外，还增加设备间通信均衡。

\[ \mathcal{L}_{CommuBal}=\alpha_3\sum^{D}_{i=1}f_i^{\prime\prime}P_i^{\prime\prime},\ f_i^{\prime\prime}=\frac{D}{MT}\sum^T_{t=1}\mathbb{I}(Token\ t\ is\ sent\ to\ Device\ i),\ P_i^{\prime\prime}=\sum_{j\in\varepsilon_i}P_j \]

训练时引入device-level token-dropping，首先计算每个设备的平均计算预算，每个设备的容量系数等于1.0，然后在每个设备上丢弃affinity score最低的token，直到达到计算预算，此外确保约10%训练序列的token永远不会被丢弃。

Transformer层数60，隐藏维度5120。权重初始化标准差0.006。注意力头数量128，每个头维度128，KV压缩维度512，query压缩维度1536，解耦QK每个头维度64。将除第一层外的所有FFN替换为MoE层，每个MoE层由2个共享专家和160个路由专家组成，每个专家的中间隐藏维度1536，每个token激活6个专家。在压缩潜在向量后使用额外的RMSNorm层，并在宽度瓶颈处(即压缩潜在向量和路由专家的中间隐藏状态)乘以额外的缩放因子。总参数236B，激活参数21B。

数据处理阶段同DeepSeek LLM，增加数据量，提升数据质量。tokenizer相同。总数据量8.1T tokens。

优化器AdamW，\(\beta_1\)=0.9，\(\beta_2\)=0.95，weight_decay = 0.1。使用multi-step learning rate scheduler，热身2000步达到最大学习率，处理60%的tokens后减少31.6%，90% tokens后再减少31.6%，最大学习率2.4e-4，梯度裁剪阈值为1.0。

使用批量大小调度策略，在前225B tokens的训练中，batch size从2304逐渐增加到9216，在剩余的训练中保持9216。最大序列长度4K。

利用YaRN把窗口长度从4K扩展到128K。将YaRN应用在解耦共享key \(\mathbf{k}^R_t\)上，scale 40，\(\alpha\) 1，\(\beta\) 32，目标最大窗口长度160K，调整了YaRN里的长度缩放因子。额外训练1000步，序列长度32K，batch size 576。

微调数据在原有基础上提升了质量，减少幻觉，提升书写水平。微调2个epoch，学习率5e-6。

通过两阶段GRPO强化学习提升代码数学能力及对齐人类偏好，第一阶段对编码和数学任务训练奖励模型，第二阶段采用多奖励架构，分别训练helpful、safety、rule based模型加权合并为奖励模型，奖励模型从SFT模型初始化。

DeepSeek V3

Paper | Code

模型架构遵循DeepSeek V2。MoE里使用sigmoid函数计算affinity scores，并在所有选定的分数里应用归一化以产生门控值。把原来的负载均衡辅助损失修改成给选择路由的每个专家affinity score添加偏置项，训练每一步结束时，如果某个专家过载就将偏置项减少\(\gamma\)，如果负载不足就增加\(\gamma\)，偏置项仅用于专家选择，门控值仍使用原有affinity score。

\[ g_{i,t}^{\prime \prime}=\left\{\begin{array}{rcl}s_{i,t} & {s_{i,t}+b_i\in Topk(\{s_{j,t}+b_i|1\leq j \leq N_r\},K_r)}\\0 & otherwise\end{array}\right. \]

添加以下complementary sequence-wise balance loss避免单一序列不均衡：

\[ \mathcal{L}_{Bal}=\alpha\sum^{N_r}_{i=1}f_iP_i,\ f_i=\frac{N_r}{K_rT}\sum^T_{t=1}\mathbb{I}(s_{i,t}\in Topk(\{s_{j,t}|1\leq j \leq N_r\},K_r)),\ s^\prime_{i,t}=\frac{s_{i,t}}{\sum^{N_r}_{j=1}{s_{j,t}}},\ P_i=\frac{1}{T}\sum^T_{t=1}s^\prime_{i,t} \]

同V2一样采用设备限制路由，但不使用丢弃token。

增加Multi-Token Prediction学习，在每个位置把预测范围扩展到多个未来的token。MTP包括D个连续模块预测D个额外token，每个模块包括一个共享Eembedding层、一个共享输出层、一个Transformer、一个映射矩阵。

\[ \mathbf{h}_i^{\prime k}=M_k[RMSNorm(\mathbf{h}_i^{k-1};RMSNorm(Emb(t_{i+k}))] \]

\[ \mathbf{h}^k_{1:T-k}=Tranformer(\mathbf{h}^{\prime k}_{1:T-k}) \]

\[ P^k_{i+k+1}=OutHead(\mathbf{h}_i^k) \]

\[ \mathcal{L}^k_{MTP}=CrossEntropy(P^k_{2+k:T+1},t_{2+k:T+1})=-\frac{1}{T}\sum^{T+1}_{i=2+k}logP^k_i[t_i] \]

\[ \mathcal{L}_{MTP}=\frac{\lambda}{D}\sum^D_{k=1}\mathcal{L}^k_{MTP} \]

训练工程优化：为流水线并行设计了新的DualPipe算法。开发了高效的cross-node all-to-all communication kernels。优化训练中多种计算的内存占用。使用FP8数据格式的混合精度框架。

数据在V2基础上，增加编码和数学比例，增加中英外多语言覆盖，总计14.8T。

DeepSeek R1

Paper | Code

介绍了三个模型：DeepSeek-R1-Zero，不做SFT直接用强化学习；DeepSeek-R1，先用SFT冷启动，再用强化学习；从DeepSeek-R1给小模型蒸馏学习。

使用DeepSeek-V3-Base作为基础模型。强化学习沿用GRPO算法。奖励为规则，包括两部分：有确定答案的直接判断是否正确，判断是否符合CoT格式。奖励模型可能受到reward hacking。

DeepSeek-R1-Zero仅靠强化学习就可获得推理能力，并且过程中会产生重新思考的能力，利用多数投票可以进一步提升性能。缺点是可读性差，语言混杂。

DeepSeek-R1先做SFT进行冷启动，然后做使用规则奖励的强化学习提升推理能力，当收敛时为后续迭代收集新的SFT数据，一类是推理数据，不再局限确定答案的问题，去除语言混杂和包含长段落或代码块的问答，另一类是非推理数据，对部分V3的SFT数据生成CoT答案，对简单问题直接生成答案。最终用800k数据微调两个epoch。最后再进行第二轮强化学习对齐价值观。

蒸馏：直接使用上面的800k生成数据通过SFT微调小模型，能增强其推理能力，比直接强化学习效果好。RL应该也能有提升。

失败尝试：Process Reward Model：难以显式定义步骤，难以判别中间步是否正确，会产生reward hacking。Monte Carlo Tree Search：搜索空间巨大容易陷入局部最优，影响生成质量的价值模型难以学习。

DeepSeek VL

Paper | Code

数据：预训练数据：图像文本交叉数据，图片说明数据，图表数据，网页代码数据，文档OCR数据，场景文本OCR数据，DeepSeek LLM的文本数据。SFT数据：开源gpt4v数据集，预训练数据集里提取的图表数据，Screen-to-code任务里提取的UI代码数据，一些网上收集的使用样例处理后的数据。

模型架构：包含三个模块：混合视觉编码器、视觉语言适配器和语言模型。混合视觉编码器结合SAM-B和SigLIP-L编码器，高分辨率SAM-B视觉编码器首先将图像大小调整为1024x1024，并生成64x64x256的特征图，VL适配器最初会将其插值为96x96x256的大小，随后采用两个步幅为2的卷积层，生成24x24x1024的特征图，并将其重塑为576x1024，除此之外，由SigLIP-L生成的大小为576x1024的低分辨率特征图与高分辨率特征连接，从而产生576个具有2048维度的视觉token，经过GeLU激活后进入embedding层。VL适配器采用两层混合MLP，最初使用不同的单层MLP分别处理高分辨率特征和低分辨率特征，拼接特征后通过另一层MLP转换为LLM的输入空间。语言模型基于DeepSeek LLM预训练模型继续预训练。

训练流水线：分为三个阶段：VL适配器热身，VL联合预训练，SFT。热身阶段，目标是在嵌入空间内的视觉和语言元素之间建立概念联系，冻结视觉编码器和LLM，只允许训练VL适配器。预训练阶段，保持冻结视觉编码器，优化语言模型和VL适配器，过多的多模态数据会导致LLM对语言能力的严重遗忘，合适的比例(多模态 : 语言=70% : 30%)可有效缓解遗忘问题，同时增强多模态能力，在1.3B模型上预训练，再通过SFT把能力扩展到7B模型，通过采用多选PPL方法来监控模型进度和以最小的比例将SFT数据引入训练数据的方法保证1.3B模型训练的稳定。SFT阶段，为节省显存冻结SAM-B参数，只监督学习答案和特殊token，不使用系统和用户提示词，使用混合多模态数据和纯文本对话数据。

DeepSeek VL2

Paper | Code

数据：VL对齐数据：ShareGPT4V。预训练数据同VL。SFT数据：一般视觉问答，OCR和文档理解，图表理解，推理逻辑和数学，教材和学术问题，Web-to-code和plot-to-Python，视觉分割，对话生成，纯文本数据。

模型架构：同样包含三个模块。视觉编码器里，通过将高分辨率图像分割成平铺来实现动态平铺策略，定义一组候选分辨率以适应不同的纵横比，\(C_R=\{(m·384,n·384)|m\in N,n\in N,1\leq m,n,mn \leq 9\}\)，对输入图片选择最小填充的比例，分割为\(m_i*n_i\)个384×384个小图和一个全局缩略图，然后使用一个SigLIP-SO400M-384视觉编码器把所有图生成embedding。VL适配器通过一个2*2像素随机化操作压缩每个小图的token数，给缩略图每行末、小图最后一列末、缩略图和小图之间添加特殊token，然后通过两层MLP映射到LLM里。LLM基于DeepSeek MoE。

训练流水线：分为三个阶段：VL对齐，预训练，SFT。对齐阶段，冻结LLM，训练视觉编码器和VL适配器。预训练阶段，训练所有参数。SFT阶段，训练所有参数，只监督学习答案和特殊token，不使用系统和用户提示词。

Janus

Paper | Code

是一个统一多模态理解和生成的自回归框架。

模型架构：对于纯文本理解、多模态理解和视觉生成，应用独立的编码方法将原始输入转换为特征，然后由统一的自回归Transformer处理，对文本理解，使用LLM内置tokenizer将文本转换为离散ID再得到对应特征表示，对多模态理解，使用SigLIP编码器从图像提取高维语义特征，再使用理解适配器将图像特征映射到LLM输入空间，对视觉生成任务，使用VQ tokenizer将图像转换为离散ID，使用生成适配器将ID对应embedding映射到LLM输入空间。拼接特征后送入LLM处理，LLM的内置预测头用于纯文本理解和多模态理解任务中的文本预测，随机初始化的预测头用于视觉生成任务中的图像预测。

训练流水线：分为三个阶段：训练适配器和图像头，统一预训练，SFT。第一阶段冻结视觉编码器和LLM，更新理解适配器、生成适配器和图像头。第二阶段解冻LLM，首先利用ImageNet-1k训练简单的视觉生成，然后利用text-to-image数据训练开放域生成任务。第三阶段微调除生成编码器之外的所有参数，只监督学习答案和特殊token，不使用系统和用户提示词，混合使用纯文本对话数据、多模态理解数据和视觉生成数据。

对于多模态理解、视觉生成和其他模态，可通过使用其他独立编码器扩展模态。

JanusFlow

Paper

模型架构：多模态理解任务里，LLM处理图像文本交叉文本，图像前后添加特殊token，文本经过tokenizer转换为embedding，图像利用编码器转换为特征，经线性变换得到embedding，拼接embedding输出LLM。图像生成里，使用rectified flow将文本序列作为条件生成对应图像，使用预训练SDXL-VAE生成，先在潜空间里采样高斯噪声，经过生成编码器得到embedding，再也当前时间步embedding拼接，LLM输出结果经生成解码器转换回潜空间，通过standard Euler solver更新状态，重复以上过程，最后通过VAE解码器解码成最终图像，利用classifier-free guidance保证生成质量。为两个任务解耦解码器，使用SigLIP-Large-Patch/16作为理解编码器提取特征，使用ConvNeXt作为生成编码器和解码器，并在他们间添加long skip connection。

训练流水线：分为三个阶段：随机初始化组件的适应，联合预训练，SFT。第一阶段训练线性层、生成编码器和生成解码器。第二阶段训练除视觉编码器以外的整个模型，最初分配了更高比例的多模态理解数据，随后提高了图像生成数据的比例以适应基于扩散模型的收敛要求。第三阶段解冻SigLIP编码器参数。

Janus Pro

Paper

模型架构同Janus。模型大小从1.5B提高到7B。

训练流程里修改第二阶段，增加ImageNet的训练时间，然后丢弃ImageNet数据，直接利用普通的文本到图像数据来训练模型。修改SFT的数据比例，将多模态数据、纯文本数据和文本转图像数据的比例从7 : 3 : 10更改为5 : 1 : 4。
